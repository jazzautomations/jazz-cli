    Instalação#

    Binários para Linux (386, amd64, arm64), Android/Termux (arm64), macOS (amd64, arm64) e Windows (amd64, arm64) saem das releases. Cada release traz um manifest.txt com a versão e o sha256 de cada binário, assinado com Ed25519 (manifest.txt.sig); os instaladores e o jazz update conferem os dois.

    Linux e macOS#

    curl -fsSL https://github.com/jazzautomations/jazz-cli/releases/latest/download/install.sh | sh

    O install.sh (sh POSIX) detecta sistema e arquitetura, baixa jazz-<os>-<arch>, confere a assinatura do manifesto (com minisign ou OpenSSL 3) e o sha256, e instala em ~/.local/bin sem sudo. Se ~/.local/bin não estiver no PATH, ele mostra a linha que você precisa pôr no ~/.zshrc/~/.bashrc (não mexe nesses arquivos sozinho).

    Opções (… | sh -s -- <opções>):

    OpçãoVariávelO que faz
    --bin-dir DIRJAZZ_BIN_DIRpasta de instalação (padrão ~/.local/bin)
    --systeminstala em /usr/local/bin, com sudo se precisar
    --version v0.7.0JAZZ_VERSIONuma release específica em vez da última
    --base-url URLJAZZ_BASE_URLpasta com manifest.txt(.sig) e os binários (ex.: um espelho seu, gerado por scripts/release.sh)
    --require-sigJAZZ_REQUIRE_SIG=1falha se a assinatura não puder ser verificada
    JAZZ_OPENSSLcaminho de um OpenSSL 3 (o openssl do macOS é LibreSSL, que não verifica Ed25519; o script também procura o OpenSSL 3 do Homebrew)

    Sem minisign nem OpenSSL 3, o script confere só o sha256 e avisa. A cópia do install.sh que está no repositório não tem a chave pública (quem a coloca é o scripts/release.sh), então ela também só confere o sha256: use a que vem anexada à release.

    macOS (Intel ou Apple Silicon): o mesmo comando. Num terminal rodando sob Rosetta o script escolhe o binário arm64 nativo.

    Linux 32 bits (i386/i686, como o Dell): o mesmo comando; ele baixa jazz-linux-386 (também num kernel 64 bits com userland 32 bits). Dicas para máquina antiga:

    • Em Debian/antiX o fd se chama fdfind; o shell do jazz cria o atalho fd sozinho.
    • O ~/.bashrc costuma sair logo no começo em shell não interativo, então ssh host 'jazz …' não acha o ~/.local/bin. Use ssh host '~/.local/bin/jazz …' ou ssh -t host 'bash -lc jazz'.
    • Sem SSH para baixar, compile em outra máquina e copie: JAZZ_DEPLOY_HOST=<alias-ssh> scripts/deploy-ssh.sh (compila linux/386, instala em ~/.local/bin e põe um atalho .desktop no menu; --sudo instala em /usr/local/bin).
    • Para o sandbox no Linux instale o bubblewrap (sudo apt install bubblewrap).

    Android (Termux)#

    Suporte da comunidade: o binário Android/arm64 compila e está incluído nas releases; ainda não foi validado em um aparelho Termux real. Use aarch64, sem root:

    pkg install curl openssl python git bash
curl -fsSL https://github.com/jazzautomations/jazz-cli/releases/latest/download/install.sh | sh

    O instalador detecta TERMUX_VERSION ou o sufixo convencional /com.termux/files/usr de PREFIX, escolhe jazz-android-arm64 e instala em $PREFIX/bin (sem sudo, sem mexer no PATH). ~/arquivo é resolvido pelo $HOME do próprio Termux. Compilação cruzada e testes locais cobrem o caminho; uso no aparelho ainda não foi verificado. O sandbox do sistema não funciona no Android: não há bubblewrap nem user namespaces. As proteções de software (cerca de caminhos, guardrails, aprovações) continuam ativas, o modo padrão é auto e o turbo cai nas regras do auto com um aviso. proot não é uma fronteira de segurança. Prefira ask ou plan no Android. Entrar em yolo sem sandbox exige consentimento explícito; em execução headless, exige --ack-no-sandbox, que não cria isolamento. jazz doctor mostra o que falta (pkg install …).

    Windows (nativo, sem WSL)#

    Ainda não testado em uso real no Windows. O porte compila para amd64/arm64 e os testes passam no windows-latest do CI, mas ninguém usou o jazz num Windows de verdade por enquanto. Relatos são bem-vindos.

    No PowerShell, sem administrador:

    irm https://github.com/jazzautomations/jazz-cli/releases/latest/download/install.ps1 | iex

    O install.ps1 baixa jazz-windows-<arch>.exe, confere a assinatura Ed25519 do manifest.txt em PowerShell puro (sem minisign/OpenSSL; escrito para o Windows PowerShell 5.1 e o PowerShell 7) e o sha256, instala em %LOCALAPPDATA%\Programs\jazz\jazz.exe e põe essa pasta no PATH do usuário. Variáveis: JAZZ_BASE_URL, JAZZ_BIN_DIR, JAZZ_ARCH (amd64/arm64), JAZZ_NO_PATH=1 e JAZZ_REQUIRE_SIG=1. Use o Windows Terminal.

    Como funciona no Windows:

    • Shell da ferramenta bash: o Git Bash quando o Git for Windows está instalado (no PATH ou em C:\Program Files\Git); senão PowerShell (pwsh, depois powershell.exe). O bash.exe do WSL (System32/WindowsApps) é ignorado de propósito. JAZZ_SHELL=bash|pwsh|powershell|<caminho> escolhe à mão. O modelo é avisado de qual shell está rodando, pra escrever na sintaxe certa. jazz doctor mostra o shell escolhido.
    • Terminal: no Windows Terminal há cores 24 bits e símbolos Unicode. No console clássico (ConHost) com VT o jazz usa 256 cores e símbolos ASCII (JAZZ_ASCII=0 força Unicode); sem VT a interface não abre e sugere o Windows Terminal ou jazz -p.
    • Pastas: config em %APPDATA%\jazz-cli (auth.json, config.json, mcp.json), dados (sessões, logs, jobs) em %LOCALAPPDATA%\jazz-cli. JAZZ_HOME continua valendo.
    • Processos: cada comando, servidor MCP, hook e script roda num job object próprio; Esc/Ctrl+C e timeout derrubam a árvore inteira, e se o jazz cair o Windows mata o que sobrou.
    • Segurança: além das regras de bash, comandos destrutivos de PowerShell/cmd pedem confirmação (Remove-Item -Recurse -Force, rd /s /q, format, iwr … | iex, -EncodedCommand, Set-ExecutionPolicy, registro, schtasks, Defender, firewall…). Não há sandbox de arquivos no Windows (só limites do job object).
    • Limitações: sob PowerShell, um programa que lê o stdin trava até o timeout (no bash ele recebe /dev/null); o $EDITOR padrão é o Bloco de Notas.

    Compilando do código#

    Go 1.27 ou mais novo:

    git clone https://github.com/jazzautomations/jazz-cli && cd jazz-cli
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o jazz .
install -m 755 jazz ~/.local/bin/jazz
# outra plataforma: CGO_ENABLED=0 GOOS=linux GOARCH=386 go build -o dist/jazz-linux-386 .

    Um binário compilado assim não tem a chave pública embutida, então o jazz update dele recusa atualizar (atualização sem assinatura não é aceita). Releases assinadas saem do scripts/release.sh (veja o cabeçalho do script).

    Atualizando#

    jazz update (ou jazz update --check) baixa a última release, confere a assinatura do manifesto, recusa versão mais velha ou diferente da anunciada e troca o binário em uso.

    Install#

    Binaries for linux (386, amd64, arm64), macOS (amd64, arm64) and Windows (amd64, arm64) ship in the releases. Each release carries a manifest.txt with the version and the sha256 of every binary, signed with Ed25519 (manifest.txt.sig); the installers and jazz update check both.

    Linux and macOS#

    curl -fsSL https://github.com/jazzautomations/jazz-cli/releases/latest/download/install.sh | sh

    install.sh (POSIX sh) detects OS and architecture, downloads jazz-<os>-<arch>, verifies the manifest signature (with minisign or OpenSSL 3) and the sha256, and installs to ~/.local/bin without sudo. If ~/.local/bin is not on your PATH it prints the line to add to ~/.zshrc/~/.bashrc (it does not edit those files).

    Options (… | sh -s -- <options>):

    OptionVariableWhat it does
    --bin-dir DIRJAZZ_BIN_DIRinstall directory (default ~/.local/bin)
    --systeminstall to /usr/local/bin, using sudo when needed
    --version v0.7.0JAZZ_VERSIONa specific release instead of the latest
    --base-url URLJAZZ_BASE_URLfolder holding manifest.txt(.sig) and the binaries (e.g. your own mirror built by scripts/release.sh)
    --require-sigJAZZ_REQUIRE_SIG=1fail when the signature cannot be verified
    JAZZ_OPENSSLpath to an OpenSSL 3 binary (macOS ships LibreSSL, which cannot verify Ed25519; the script also looks for Homebrew's OpenSSL 3)

    Without minisign or OpenSSL 3 the script checks only the sha256 and warns. The copy of install.sh in the git repository has no public key (scripts/release.sh fills it in), so it also checks only the sha256: use the one attached to the release.

    macOS (Intel or Apple Silicon): same command. In a terminal running under Rosetta the script picks the native arm64 binary.

    32-bit Linux (i386/i686, like the Dell): same command; it downloads jazz-linux-386 (also on a 64-bit kernel with a 32-bit userland). Tips for old machines:

    • On Debian/antiX fd is called fdfind; jazz's shell creates the fd alias itself.
    • ~/.bashrc usually returns early for non-interactive shells, so ssh host 'jazz …' does not find ~/.local/bin. Use ssh host '~/.local/bin/jazz …' or ssh -t host 'bash -lc jazz'.
    • To cross-compile on another machine and copy over SSH: JAZZ_DEPLOY_HOST=<ssh-alias> scripts/deploy-ssh.sh (builds linux/386, installs to ~/.local/bin and adds a .desktop menu entry; --sudo installs to /usr/local/bin).
    • For the Linux sandbox install bubblewrap (sudo apt install bubblewrap).

    Android (Termux)#

    Community-supported: we cannot test on a device here, so please report what breaks. aarch64, no root:

    pkg install curl openssl python git bash
curl -fsSL https://github.com/jazzautomations/jazz-cli/releases/latest/download/install.sh | sh

    The installer detects Termux (TERMUX_VERSION/PREFIX) and installs to $PREFIX/bin (no sudo, no PATH edit). Works: the agent, the ask/auto/plan/yolo modes, built-in scripts (python3/sh from PATH), the persistent bash shell, temp files in $PREFIX/tmp, and low-power rendering on by default (JAZZ_LOW_POWER=0 turns it off). Does not work: the OS sandbox, since Android has no bubblewrap or user namespaces. Software protections (path fence, guardrails, approvals) stay on, the default mode is auto, and turbo falls back to the auto rules with a notice. proot is not a security boundary. jazz doctor lists what is missing (pkg install …).

    Windows (native, no WSL)#

    Not runtime-tested on Windows yet. The port builds for amd64/arm64 and the test suite passes on CI's windows-latest, but nobody has used jazz on a real Windows machine so far. Reports welcome.

    In PowerShell, no admin needed:

    irm https://github.com/jazzautomations/jazz-cli/releases/latest/download/install.ps1 | iex

    install.ps1 downloads jazz-windows-<arch>.exe, verifies the Ed25519 signature of manifest.txt in pure PowerShell (no minisign/OpenSSL; written for Windows PowerShell 5.1 and PowerShell 7) and the sha256, installs to %LOCALAPPDATA%\Programs\jazz\jazz.exe and adds that folder to the user PATH. Variables: JAZZ_BASE_URL, JAZZ_BIN_DIR, JAZZ_ARCH (amd64/arm64), JAZZ_NO_PATH=1, JAZZ_REQUIRE_SIG=1. Use Windows Terminal (24-bit color and Unicode; the classic console falls back to 256 colors and ASCII). The bash tool uses Git Bash when Git for Windows is installed, otherwise PowerShell (JAZZ_SHELL overrides; WSL's bash.exe is skipped on purpose). Every command, MCP server, hook and script runs in its own job object. There is no file sandbox on Windows (job-object limits only).

    From source#

    Go 1.27 or newer:

    git clone https://github.com/jazzautomations/jazz-cli && cd jazz-cli
CGO_ENABLED=0 go build -trimpath -ldflags="-s -w" -o jazz .
install -m 755 jazz ~/.local/bin/jazz
# another platform: CGO_ENABLED=0 GOOS=linux GOARCH=386 go build -o dist/jazz-linux-386 .

    A binary built this way has no embedded public key, so its jazz update refuses to update (unsigned updates are never accepted). Signed releases come from scripts/release.sh.

    Updating#

    jazz update (or jazz update --check) downloads the latest release, verifies the manifest signature, refuses an older version or one that differs from what was advertised, and replaces the running binary.
