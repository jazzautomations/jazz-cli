    Configuração#

    Pastas (respeitam XDG_CONFIG_HOME/XDG_DATA_HOME; JAZZ_HOME muda as duas):

    ArquivoPara quê
    ~/.config/jazz-cli/config.jsonmodelo, fallback, modo, provedores, omni, permissions, hooks, skills, recover, plan_cache, hindsight (e as chaves da v0.4 em DESIGN.md)
    ~/.config/jazz-cli/auth.jsonchaves e tokens (0600; nunca vão pro shell, MCP ou hooks)
    ~/.config/jazz-cli/mcp.jsonservidores MCP globais
    ~/.config/jazz-cli/trusted.jsonprojetos em que você confiou
    ~/.config/jazz-cli/AGENTS.md, skills/, commands/instruções, skills e comandos globais
    ~/.local/share/jazz-cli/sessões (JSONL), logs de debug, cota, cache de update, cache de planos (plans/)

    MCP#

    Global em ~/.config/jazz-cli/mcp.json, do projeto em .mcp.json na raiz (mesmo formato do Claude Code). O .mcp.json do projeto só vale depois de jazz trust (ou de você aceitar a pergunta no modo interativo); um servidor do projeto nunca substitui um global de mesmo nome, e ${VAR} no projeto só expande variáveis seguras ou listadas em project_env do arquivo global. Use enabled_tools/disabled_tools por servidor e /mcp pra ver o status.

    Resources e prompts. Servidores que declaram as capacidades resources / prompts ganham duas ferramentas para o modelo: mcp_resource {server, uri} (lê um recurso; uri vazio lista recursos e templates; subscribe: true assina atualizações quando o servidor suporta) e `mcp_prompt {server, name, args}(busca um prompt preenchido;name` vazio lista os prompts e seus argumentos). O prompt de sistema leva só as contagens (“12 recursos, 3 templates em 2 servidores”), nunca a lista, então o cache de prompt não muda; o modelo lista chamando a ferramenta. Texto grande vai truncado com o original num arquivo de spill; blob binário é decodificado para um arquivo 0600 e o modelo recebe só um resumo (imagem pequena vira anexo). Tudo passa pela mesma sanitização e detecção de injection dos resultados de fetch/MCP e vem dentro de <untrusted_tool_output server=…>. O catálogo (recursos, templates, prompts) entra no hash anti rug-pull como as descrições de tools: se o servidor muda a lista depois de você ver, a próxima chamada pede confirmação. No chat: /mcp resources e /mcp prompts listam tudo como servidor:uri. Desligar: "disable_resources": true / "disable_prompts": true no servidor, ou JAZZ_MCP_RESOURCES=off para todos.

    Permissões#

    Regras no formato do Claude Code (Bash(npm test:*), Edit(src/**), Read(.env), WebFetch(domain:go.dev), mcp__srv__*), lidas de:

    • config.json → permissions.allow|deny|ask
    • ~/.claude/settings.json
    • .claude/settings.json e .claude/settings.local.json do projeto
    • .jazz/settings.json do projeto (onde a opção 2 da pergunta, "Sim, e não perguntar de novo", e o /permissions add gravam; a opção 2 numa edição vale só para a sessão, veja always_scope)

    deny > ask > allow. As regras allow do projeto só valem com o projeto confiado; deny/ask sempre valem.

    Hooks#

    PreToolUse, PostToolUse, UserPromptSubmit, Stop e SessionStart, no formato do settings.json do Claude Code, nos mesmos arquivos das permissões (chave hooks). Rodam com bash -c na raiz do projeto, recebem JSON no stdin, timeout de 60 s; saída 2 bloqueia.

    Instruções do projeto#

    AGENTS.md global e um por pasta, da raiz do git até a pasta atual (AGENTS.override.md › AGENTS.md › CLAUDE.md). Skills em ~/.config/jazz-cli/skills, .jazz/skills e .claude/skills (no máximo 12 na lista do prompt, descrição cortada em 120 caracteres). ~/.claude/skills só entra com "skills": {"claude_dir": true} no config.json: lá costumam morar dezenas de skills grandes de outros agentes, que custam milhares de tokens.

    Skills embutidas#

    O jazz traz 13 skills curtas dentro do binário (surgical-change, verify-done, debug-loop, tdd-lite, write-tests, refactor-safely, git-hygiene, explore-codebase, shell-safety, plan-small, old-coder-gauntlet, review-diff, frontend-craft). A frontend-craft (piso de qualidade, proibições e os 4 modos Persuadir/Operar/Ler/Experiência, reescrita a partir do Impeccable) entra em pedidos de design/UI/tela/página/landing/dashboard e na primeira edição de um arquivo de UI. O modelo não vê a lista: o próprio jazz escolhe por palavras-chave (PT e EN) no pedido, arquivos editados (*_test.go, *.spec.*…), sinais na saída das ferramentas (teste falhando, stack trace, conflito de merge, rm -rf, sed -i, diff passando de 40 linhas) e a fase do turno. No máximo uma por turno e três por sessão; entra uma vez como <system-reminder> na mensagem do usuário ou no resultado da ferramenta que disparou (o prompt de sistema não muda, o cache continua valendo) e volta depois de compactar. Aparece como skill aplicada: <nome>; com --debug, cada decisão vai pro log ("kind":"skill", candidatos com pontuação e motivo de pular).

    • config.json: "skills": "auto" (padrão) · "manual" (só /skill) · "off", ou o objeto {"mode": "auto", "claude_dir": false, "threshold": 3, "per_turn": 1, "per_session": 3}.
    • JAZZ_SKILLS=off|auto|manual passa por cima da config (bom pra comparar A/B no eval).
    • /skill lista; /skill <nome> [pedido] força uma no próximo turno.

    Steering (regras condicionais)#

    Regras no formato do Kiro em .jazz/steering/*.md (também .kiro/steering/*.md) e do Cursor em .cursor/rules/**/*.mdc; globais em ~/.config/jazz-cli/steering/*.md (uma regra do projeto substitui a global de mesmo nome). O front matter decide quando a regra entra:

    ---
inclusion: fileMatch            # always (padrão) | fileMatch | auto | manual
fileMatchPattern: "**/*.{ts,tsx}"   # ou uma lista
description: convenções da API  # usada por auto
---
Texto da regra.
    • always (Cursor: alwaysApply: true): vai no prompt de sistema, fixo na sessão.
    • fileMatch (Cursor: globs): entra uma vez por sessão, como lembrete, no resultado do primeiro read/edit/write que tocar um arquivo que casa. O prompt não muda, então o cache continua valendo; padrão sem / casa o nome do arquivo em qualquer pasta.
    • auto (Cursor: só description) e manual: aparecem numa lista no prompt, como as skills; o modelo lê quando a tarefa casa com a descrição ou quando você pede (#nome).

    As regras do projeto passam pelo portão de confiança (jazz trust), como .mcp.json e hooks: mudou o arquivo, pergunta de novo. Links simbólicos e arquivos acima de 64 KB são ignorados.

    MCP, hooks, skills#

    • MCP: global servers in ~/.config/jazz-cli/mcp.json, project servers in .mcp.json (same format as Claude Code), the latter only after jazz trust. A project server never replaces a global one with the same name. enabled_tools/disabled_tools per server; /mcp shows status. Servers that declare resources / prompts get two model tools, mcp_resource {server, uri} and mcp_prompt {server, name, args} (empty uri/name lists). The system prompt carries only counts, results are sanitized and wrapped as untrusted like fetch, and a changed catalogue needs re-approval (rug-pull hash). /mcp resources and /mcp prompts list them; turn off with disable_resources / disable_prompts per server or JAZZ_MCP_RESOURCES=off.
    • Permissions: Claude Code rule format (Bash(npm test:*), Edit(src/**), Read(.env), WebFetch(domain:go.dev), mcp__srv__*) from config.json, ~/.claude/settings.json, .claude/settings*.json and .jazz/settings.json. deny > ask > allow.
    • Hooks: PreToolUse, PostToolUse, UserPromptSubmit, Stop, SessionStart, in Claude Code's settings.json format. They get JSON on stdin, 60 s timeout; exit 2 blocks.
    • Skills: 13 short built-in skills (surgical-change, verify-done, debug-loop, tdd-lite, write-tests, refactor-safely, git-hygiene, explore-codebase, shell-safety, plan-small, old-coder-gauntlet, review-diff, frontend-craft). The model never sees the list: jazz picks at most one per turn from keywords, edited files, tool-output signals and the turn phase, and injects it as a reminder (the system prompt stays fixed). frontend-craft (quality floor, bans and the Persuade/Operate/Read/Experience modes, rewritten from Impeccable) kicks in for UI/design requests and the first edit of a UI file; after each UI edit the deterministic ui_lint hook appends findings (gradient text, default violet palette, emoji as icons, missing alt, outline: none without :focus-visible, motion without prefers-reduced-motion…). Your own skills go in ~/.config/jazz-cli/skills, .jazz/skills or .claude/skills; /skill lists them.
    • Steering: conditional rules in Kiro format (.jazz/steering/*.md, .kiro/steering/*.md) and Cursor format (.cursor/rules/**/*.mdc): always, fileMatch, auto, manual.
    • Scripts: a script tool with 19 built-in Python/sh scripts that answer in short JSON (detect_project, run_tests, parse_test_output, git_state, ui_lint…); jazz script runs them without a model. Plus model-free shortcuts ("run the tests", "git status") and an offline mode.
    • Offline brain (0.9): with no model (or in -p for clear read-only requests), a classical interpreter (47 intents, typo-tolerant project and machine entities: "talscle status" runs tailscale status) turns the request into an explicit task state executed by methods with preconditions and verifiers (open_file, run_tests, git_status, env_status, tool_status…); "done" only with evidence, otherwise "unverified". jazz env profiles the machine, jazz eval offline runs 39 model-free tasks (39/39 on the 2005 reference laptop, 120–139 ms for "open README.md" versus 15–21 s and 32k tokens before).

    The full reference (all commands, slash commands, configuration files, how omni routes, output parsing, budgets, --recover, plan cache, troubleshooting) is in the Portuguese README.
